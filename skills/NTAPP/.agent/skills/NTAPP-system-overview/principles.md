# Evidence Policy & Operational Principles

> Tham chiếu từ [workflow.md](./workflow.md) và 2 mode file. File này là nguồn duy nhất — KHÔNG lặp lại nội dung trong step file.

---

## Tier 1 — Body sections (prose, Assumption cho phép)

Áp dụng cho: Executive Summary, Architecture Overview narrative, Business Features description, Main Processing Flows narrative, Technical Assessment, Risks & Recommendations.

**Cho phép:** Suy luận business intent từ naming + comment + workflow + SQL. Khi không chắc → prefix `**Assumption:** ...` ngay trong dòng tương ứng.

**Mục đích:** Tài liệu phải đọc được như prose, không phải bảng dày đặc TODO. Reader (BA / dev mới) cần "câu chuyện" của service, không chỉ là evidence chain.

**Vi phạm:** Bịa fact mà không tag `Assumption:` → SAI. Tag rõ ràng = đủ.

---

## Tier 2 — Bảng API / Integration / Data Model (evidence required)

Áp dụng cho: Section "API Analysis" tables, Section "Integration Analysis" tables, Section "Database Analysis" tables, Section "Full Feature List" table.

**Yêu cầu:** Mỗi row PHẢI có cột "File evidence" trỏ file:line trong code repo. Thiếu → dán `<TODO: SA verify — câu hỏi cụ thể>` ở cột đó. KHÔNG xóa row, KHÔNG bịa endpoint / DB table / auth header.

**Phép trích hợp lệ:** Route registration, OpenAPI/proto/GraphQL file, ORM model class với file:line, env file content, config YAML.

---

## Tier 3 — Cross-System Contract Match Matrix (mode baseline only, strict)

Áp dụng cho: `cross_system_overview.md` Section "Contract Match Matrix".

**Yêu cầu:** Mỗi entry là kết quả CROSS-REFERENCE giữa Section 0 của ≥2 sub-system. KHÔNG Assumption. 5 status:

| Status | Định nghĩa | Evidence trace |
|---|---|---|
| `MATCHED` | Provider (IDL Provided) ↔ Consumer (IDL Consumed) khớp version + DTO | 2 file:line (cả provider + consumer) |
| `VERSION-MISMATCH` | Endpoint khớp path/method nhưng version khác | 2 file:line + diff version |
| `CONSUMER-ONLY` | Consumer gọi endpoint không có provider trong scope | Consumer file:line + note "provider không phát hiện" |
| `PROVIDER-ORPHAN` | Provider expose endpoint không có consumer trong scope | Provider file:line + note "consumer không phát hiện" |
| `DTO-DRIFT` | Path/method khớp nhưng request/response schema khác | 2 file:line + diff field |

**KHÔNG bịa status.** Khi không đủ evidence để classify → dán `UNKNOWN` + TODO câu hỏi.

## R-Mode-Default: baseline là mode mặc định

Không nêu `--mode` → chạy `baseline`. `overview` chỉ chạy khi user gõ tường minh `--mode overview` hoặc chọn option (e) ở scope confirm.

Skill KHÔNG tự hạ mode xuống `overview` để né gate multi-root hay né Q&A loop — gate fail thì HALT và trả quyết định cho user.

---

## R-Scope: Multi-Root Workspace (mode baseline only — tức mặc định)

Mode `baseline` BẮT BUỘC workspace có ≥1 code repo ngoài CWD. Nếu rỗng → HALT ở STEP 1.3 (`workflow.md`).

Mode `overview` không enforce — chạy được ở single-folder workspace.

---

## R-Scope-Honesty: Detected vs Scope (mode baseline only)

Mode baseline phải log:
- `detected_list` (toàn bộ code repo phát hiện)
- `scope_list` (user confirm scan)
- `out_of_scope_list` = `detected \ scope`

Cross-system overview Section "Detected vs Scope" liệt kê đủ 3, kèm lý do skip (nếu user nêu) hoặc `<TODO: SA verify — lý do out-of-scope?>`.

Skill KHÔNG được tự thêm repo vào scope. Detect ≠ scope.

---

## R-TODO format

Khi thiếu fact ở Tier 2 / Tier 3 → bắt buộc format:

```
<TODO: SA verify — {câu hỏi cụ thể, hành động được}>
```

**Quy tắc:**
- `SA verify` là literal — pre-commit / grep search dùng prefix này.
- 1 marker = 1 câu hỏi (không gom).
- Đặt đúng cell/dòng cần fact, không gom cuối file.

**Tốt:** `<TODO: SA verify — service auth-svc gọi notification-svc qua HTTP hay gRPC?>`
**Tệ:** `<TODO: SA verify>` (vague), `<TODO: SA verify — kiểm tra hết>` (over-scope).

## R-Best-Effort header

Mọi file output có frontmatter YAML + dòng cảnh báo đầu file:

```yaml
---
generated_by_skill: ntapp-system-overview
mode: <overview|baseline>
repo: {repo_name}
date: {YYYY-MM-DD}
status: best-effort-{overview|baseline}
---
```

Body mở đầu:
```markdown
> **⚠️ Best-effort document.** Generated by `/ntapp-system-overview --mode <X>` từ `{repo_abs_path}` ngày {date}.
> Tier 1 (body) cho phép Assumption. Tier 2 (bảng API/Integration) yêu cầu evidence. SA verify trước khi dùng làm input quyết định kiến trúc.
```

## R-No-PRD/HLD

Skill này KHÔNG sinh PRD, KHÔNG sinh HLD, KHÔNG sinh roadmap. Output chỉ là descriptive snapshot của hệ thống hiện tại (brownfield) hoặc per-repo overview. Recommendation trong Section 9 (Risks) là **gợi ý**, không phải plan.

Downstream skill (`/ntapp-architecture-design`, `/ntapp-create-prd`) tiêu thụ output này, không phải skill này tự gen.
